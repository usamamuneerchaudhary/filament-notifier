# Changelog

All notable changes to this package are documented in this file.

## [2.0] - 2026-10-11

### Added

- Filament in-app channel (`in_app`) that delivers to the panel bell icon via `sendToDatabase()`.
- Self-service Notification Preferences page, plus a reusable `<livewire:notifier-preferences />` component.
- Signed one-click unsubscribe links, `List-Unsubscribe` / `List-Unsubscribe-Post` email headers, and a confirmation page.
- Delivery webhooks for Mailgun, Postmark, SES (via SNS), and Twilio, with signature verification.
- Richer delivery statuses (`pending`, `sending`, `sent`, `delivered`, `bounced`, `complained`, `failed`) and a `NotificationStatusUpdated` event.
- Retry with configurable exponential backoff, fallback channels, and Filament "Retry" / "Retry failed" actions.
- Per-user and per-channel rate limits, plus a `defer` mode that queues instead of dropping.
- Signed click-tracking URLs and a host allow-list for unsigned redirects.
- HTML-escaped `{{variable}}` substitution in HTML emails, with `{{{variable}}}` for trusted HTML.
- `Notifier::fake()` with `assertSent`, `assertSentTo`, `assertNotSent`, `assertSentCount`, and related helpers.
- CI generated by [laravel-slipway](https://github.com/usamamuneerchaudhary/laravel-slipway) (`.github/workflows/slipway.yml`).
- `CHANGELOG.md` and `UPGRADE.md`.

### Changed

- PHP 8.3+, Laravel 11–13, and Filament 4–5.
- Push notifications use the FCM HTTP v1 API (service account). The legacy server key no longer works.
- Preferences API routes now require authentication (`auth:sanctum` when Sanctum is installed, otherwise `web` + `auth`).
- `sendNow()` delivers synchronously. `schedule()` queues a notification once, at the scheduled time.
- `sendToChannel()` and `schedule()` honour user preferences.
- Tracking tokens are stored on an indexed column.
- Click-through rate is treated as the primary engagement metric (Apple Mail Privacy Protection inflates opens).

### Fixed

- Scheduled notifications were also dispatched immediately.
- Click tracking could redirect to an arbitrary http(s) host.
- Template variables were inserted unescaped into HTML emails.
- The preferences API had no authentication middleware.
- The preferences page existed but was never registered on the panel.
