# Upgrade Guide

## 1.5 to 2.0

2.0 is additive at the database layer. Run the new migrations after updating the package. A few configuration and environment requirements changed.

### Requirements

| | 1.5 | 2.0 |
| --- | --- | --- |
| PHP | 8.2+ | **8.3+** |
| Laravel | 11, 12, 13 | 11, 12, 13 |
| Filament | 4 or 5 | 4 or 5 |

### 1. Update the package

```bash
composer require usamamuneerchaudhary/filament-notifier:^2.0
php artisan vendor:publish --tag=notifier-migrations
php artisan migrate
```

New columns on `notifier_notifications`: `tracking_token`, `event_key`, `attempts`, `next_retry_at`, `delivered_at`, `bounced_at`, `complained_at`, `provider_message_id`, `fallback_for_notification_id`. Existing `data.tracking_token` values are copied onto the new column.

### 2. PHP 8.3

Laravel 13 already requires PHP 8.3. If you are still on Laravel 11 or 12 with PHP 8.2, upgrade PHP before installing 2.0.

### 3. Authenticate the preferences API

`GET`/`PUT /api/notifier/preferences` now requires a signed-in user. The default middleware is `api` + `auth:sanctum` when Laravel Sanctum is installed, otherwise `web` + `auth`. Override it:

```php
// config/notifier.php
'api' => [
    'middleware' => ['api', 'auth:sanctum'],
],
```

Unauthenticated calls that previously 500 now return 401 or a login redirect.

### 4. Push (FCM)

The legacy `https://fcm.googleapis.com/fcm/send` server-key API is gone. Replace `firebase_server_key` on the Push channel with:

- `firebase_project_id`
- `firebase_service_account` (the service account JSON, or an absolute path to it)

The device token is still read from `$user->fcm_token` or `$user->push_token`.

### 5. Click tracking redirects

New tracking links are signed. Unsigned legacy links only redirect to:

- a URL that already appeared in that notification, or
- the application host, or
- hosts listed in `config('notifier.tracking.allowed_hosts')`

Everything else redirects home. Re-send important emails if you still rely on unsigned tracking links to third-party hosts.

### 6. HTML templates

`{{variable}}` in HTML emails is now escaped. Use `{{{variable}}}` only for trusted HTML.

### 7. Rate limiting

Exceeding a limit still **drops** the notification by default. To queue it instead:

```env
NOTIFIER_RATE_LIMIT_MODE=defer
```

Optional extra limits (`max_per_user_per_hour`, `max_per_user_per_day`, `max_per_channel_per_minute`) default to off (`0`).

### 8. In-app channel

To use Filament's bell icon:

```bash
php artisan make:notifications-table
php artisan migrate
```

Then add `->databaseNotifications()` to the panel. `notifier:install` warns if the `notifications` table is missing.

### 9. Preferences page

The panel now shows **Notification Preferences** for signed-in users. Hide it with:

```php
FilamentNotifierPlugin::make()->preferencesPage(false)
```

Embed the same UI outside Filament with `<livewire:notifier-preferences />`.

### 10. `Notifier::fake()`

Host-app tests can swap the real manager:

```php
use Usamamuneerchaudhary\Notifier\Facades\Notifier;

$fake = Notifier::fake();

// ... code that calls Notifier::send()

$fake->assertSent('user.registered');
$fake->assertSentTo($user, 'user.registered');
$fake->assertSentCount(1);
```

### 11. CI

The GitHub Actions workflow is generated by [laravel-slipway](https://github.com/usamamuneerchaudhary/laravel-slipway). Do not edit `.github/workflows/slipway.yml` by hand. Change `slipway.php` and run `composer slipway:compile`.
